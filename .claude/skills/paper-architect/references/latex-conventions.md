# Project LaTeX writing conventions

Cross-cutting style rules. Apply to every section drafted by `/paper write`,
every caption emitted by `/figure new`, and any other English prose this plugin
writes into `outputs/papers/<venue>/<direction>/`. Complements the per-section
heuristics in `references/section-heuristics.md` (those are kind-specific:
intro, method, results, ...). When a venue-specific note in `_venue.md`
conflicts with a rule here, project rules win.

The file is structured the same way as `section-heuristics.md` so Stage 6 can
prepend any single section as a prelude.

---

## section: hard-rules

Three rules that **must hold** in every `.tex` file under
`outputs/papers/<venue>/<direction>/`. They are stricter than style heuristics
and are enforced by a post-write grep (see SKILL.md Stage 6).

### 1. No semicolons in English prose

- **Do:** rewrite a clause-joining `;` as two sentences, a comma plus
  conjunction (`and`, `while`, `whereas`, `because`), or a colon when one side
  introduces or explains the other.
- **Don't:** use `;` to glue two independent clauses, even when grammatically
  correct.
- **Exempt:** `;` inside LaTeX macros (`\;` thin space, `\;` inside math),
  `;` inside code or BibTeX listings, `;` inside file paths or command output
  reproduced verbatim.
- **Lint pattern (Stage 6):** grep each line for `;` and report any hit that is
  not preceded by `\` and not inside a `verbatim`, `lstlisting`, or `minted`
  environment. Print line numbers. Do not auto-edit.

### 2. No em-dashes or en-dashes as prose punctuation

- **Do:** restructure with a comma, parentheses, a colon, or two sentences.
- **Don't:** use `---` (em-dash) or `--` (en-dash) to set off a clause, even
  for emphasis.
- **Exempt:** `--` inside a numeric range (`pages 2--4`, `2025--2027`).
- **Lint pattern (Stage 6):** grep for `---` anywhere and for `--` that does
  not match `\d+--\d+`. Print line numbers. Do not auto-edit.

### 3. Chinese translation comments above every English paragraph

- **Do:** whenever you write or rewrite an English paragraph in a `.tex` file
  generated by `/paper write`, place the Chinese translation immediately above
  the paragraph as `%` LaTeX comments. One `%` line per English source line,
  wrap to a similar visual width.
- **Do:** when a Chinese comment block already exists above a paragraph you
  rewrite, update the Chinese to match the new English. The two must stay in
  sync.
- **Don't:** apply this rule to `algorithms/*.tex` (owned by `/pseudocode`),
  to BibTeX entries in `refs.bib`, or to the LaTeX preamble. The rule covers
  body prose only.
- **Shape (example):**
  ```
  % 我们提出 KPred，一种基于核函数的预测器，
  % 它在长序列推理上比现有最优方法快 3.2 倍。
  We present KPred, a kernel-based predictor that runs 3.2 times faster than
  the prior best on long-context inference.
  ```

## section: math-notation

- **Do:** scalars in lowercase Latin. Use `\ell` instead of `l` (visual
  confusion with the digit `1`).
- **Do:** vectors in lowercase bold (`\mathbf{x}`), matrices in uppercase bold
  (`\mathbf{X}`), sets in `\mathcal{X}`, number fields and expectations in
  `\mathbb{R}` / `\mathbb{E}`, structured objects like sequences, trees, and
  graphs in `\boldsymbol{\sigma}`.
- **Do:** match element symbols to their set symbols. An element of
  `\mathcal{X}` is `x`, an element of `\mathcal{V}` is `v`.
- **Do:** put multi-letter names in `\textrm{}` or `\textit{}`. `\textrm{softmax}`,
  not `softmax` as raw math letters.
- **Do:** use built-in operators: `\arg\max`, `\sin`, `\tanh`, `\exp`, `\log`,
  `\min`, `\max`.
- **Do:** wrap tall content in `\left ... \right`, and use `\middle` for
  internal splits.
- **Do:** group equations with `align`. Number only equations referenced
  elsewhere in the paper; for the rest, append `\nonumber`.
- **Don't:** use `eqnarray`.
- **Do:** treat a formula as part of the sentence. Punctuate it (`,` or `.`
  after the formula as the sentence demands). Capitalize the next word only if
  a new sentence starts after the formula.

## section: tables-and-figures

- **Do:** use `booktabs` (`\toprule`, `\midrule`, `\bottomrule`) for every
  table.
- **Don't:** add vertical rules.
- **Do:** make the caption answer *what is this*. Let the body text answer
  *what does it mean*. The reader should be able to read the caption alone and
  know what the figure or table shows.
- **Do:** ship figures as vector PDF (or vector SVG converted to PDF). The
  matplotlib `save_all` helper already writes PDF, and `/figure new` exports
  SVG to PDF via cairosvg.
- **Don't:** embed PNG, JPG, or other raster art inside a figure that needs to
  scale or print cleanly.
- **Do:** size figure text between body and caption sizes. In a two-column
  layout that usually means 7–8 pt.
- **Do:** design every figure to survive grayscale printing. Test by removing
  color. Lines should remain distinguishable by dash pattern, marker shape, or
  position.
- **Do:** keep the color count to about six total, used consistently within
  functional modules. The same color means the same role across all figures in
  the paper.
- **Do:** keep arrow flow consistent. One general direction (left-to-right or
  top-to-bottom) for the whole figure.
- **Do:** prefer visual encodings (shape, position, line style) over text
  labels for repeated information.

### Caption format (figures and tables)

These rules apply to every `\caption{...}` line — whether produced by
`/figure new`, `/paper write`, or hand-edited. They are adapted from
[awesome-ai-research-writing](https://github.com/Leey21/awesome-ai-research-writing)
"生成图的标题" / "生成表的标题" entries.

- **Do:** decide case by syntax. A **noun phrase** uses Title Case (every
  content word capitalized) with **no trailing period**. A **complete
  sentence** uses Sentence case (only the first word + proper nouns
  capitalized) and **ends with a period**.
  - Noun phrase: `Architecture of KPred`
  - Sentence: `KPred achieves a 3.2x speedup over the prior best.`
- **Don't:** open a caption with `The figure shows ...`, `This diagram
  illustrates ...`, `In this figure we present ...`. Start directly with
  the subject: `Architecture of ...`, `Performance comparison of ...`,
  `Visualization of ...`.
- **Don't:** use `showcase`, `depict`, or other padding vocabulary. Use
  `show`, `compare`, `present`, `report` instead.
- **Do:** prefer the standard table-title patterns when they fit:
  `Comparison with ...`, `Ablation study on ...`, `Results on ...`,
  `Effect of ... on ...`. These read as familiar to a reviewer skimming
  the table of contents.
- **Don't:** include the `Figure 1:` / `Table 1:` prefix in the source —
  `\caption{...}` and the figure/table counter handle that automatically.
  The caption argument carries only the content.
- **Do:** escape `%`, `_`, `&` inside the caption argument. Keep `$...$`
  math intact.
- **Cross-skill enforcement:** when `/figure new` Step 6 collects an
  `intent:` line in Chinese, polish it to an English caption per these
  rules before emitting the LaTeX `\caption{...}` snippet. When
  `/paper write` drafts a section that includes a figure or table, it
  applies these rules to every new caption it writes.

## section: word-choice-and-grammar

- **Don't:** use contractions. Write `do not`, not `don't`. Write `it is`,
  not `it's`.
- **Do:** prefer `of` constructions over `'s` possessives. `the output of the
  model`, not `the model's output`. (Acceptable exception when the `'s` form
  is shorter and unambiguous in a heavily noun-stacked sentence.)
- **Do:** use Latin abbreviations sparingly and always followed by a comma.
  `e.g.,` for examples, `i.e.,` for clarification, `et al.` for authors with
  three or more co-authors.
- **Do:** put a non-breaking tie before every cross-reference. `Figure~\ref{...}`,
  `Section~\ref{...}`, `Table~\ref{...}`, `\citet{...}`.
- **Do:** match articles to pronunciation, not spelling. `an LSTM`, `a CNN`,
  `an SVM`, `a UNet`.
- **Do:** capitalize model, method, and dataset names consistently across the
  paper. `BERT`, never `Bert` or `bert`. `ImageNet`, never `imagenet`.
- **Do:** define every acronym on first use, then use the acronym consistently.
  Avoid redefining the same acronym in a later section.
- **Do:** watch hyphenated modifiers. `end-to-end training` (adjective before
  a noun) but `trained end to end` (adverbial after the verb).

## section: tense-and-tone

- **Do:** default to simple present. `KPred achieves a 3.2x speedup`, not
  `KPred achieved a 3.2x speedup`.
- **Don't:** use absolutes like `always`, `never`, `all`, `every`. Prefer
  `often`, `typically`, `in most cases`, `for the workloads we tested`.
- **Do:** keep one idea per sentence. Break long compound sentences.
- **Do:** separate observation, hypothesis, method, and result into distinct
  sentences or paragraphs. Do not conflate them.
- **Do:** minimize pronouns. Repeat the noun when ambiguity is possible.
  `it` and `they` are pitfalls when the reader has lost track of the
  antecedent.
- **Don't:** call a result `good`, `better`, or `improved` without
  quantifying. State *what* improved and *by how much*: `KPred improves
  end-to-end latency by 42% over Baseline at batch size 64`.

## section: citations-and-references

- **Do:** use `\citet{X}` when the author is the sentence subject:
  `\citet{Smith2024} report ...`.
- **Do:** use `\citep{X}` for parenthetical citations:
  `... a known result \citep{Smith2024}`.
- **Do:** pick one of `\citet`/`\citep` per role and stay consistent across
  the whole paper.
- **Do:** cite the published version (conference, journal, workshop) when
  both a venue and an arXiv preprint exist.
- **Do:** keep `.bib` entries uniform across the file. Same conference name
  spelling, same year format, same title capitalization style, same author
  field shape (last, first vs. first last).
- **Do:** place `\cite{}` consistently with respect to punctuation. If the
  citation refers to the whole preceding clause, put it after the
  punctuation. Otherwise put it before. Pick one convention per paper.

## section: paragraph-layout

- **Do:** watch every paragraph's trailing line. If it is shorter than about
  a quarter of the column width, it wastes space. Tighten or extend the
  paragraph by a sentence.
- **Do:** if a paragraph ends one short word past the column break, try
  `\looseness=-1` at the start of the paragraph. It pulls a widow word back
  into the previous line.
- **Don't:** insert a `~` or a manual `\\` to fake-fill a trailing line. The
  resulting layout breaks under any reflow.

## section: pre-submission-checklist

Run this checklist the day before the deadline, then run it again the morning
of.

- **Blind review:** strip every author name, affiliation, and acknowledgement.
  Remove them from PDF metadata too (`pdfinfo paper.pdf` should show no
  identifying author field). Strip them from supplementary code.
- **Page count:** confirm the page count after every figure or table change.
  Some venues count references, some do not. Re-read the call.
- **Title and abstract match the submission system:** the PDF's
  `\title{}` and the abstract block must match what you typed into the
  submission form. Mismatches are flagged in review.
- **Strip hardcoded paths from supplementary code:** no `/home/<user>/`, no
  `~/Desktop/`, no machine-specific data roots.
- **Strip `.git/` and similar from the supplementary archive:** check the
  archive before upload.
- **Back up the project the day before:** Overleaf and similar services slow
  down under deadline load. Local backup makes the slowdown survivable.
- **Submit at least a day early:** server load near the deadline is the
  single largest cause of failed submissions.
